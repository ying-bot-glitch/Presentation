项目概览

核心目标

从一种产品开始，通过 4-5 轮 AI 辅助的提取与问答，沉淀出可复用的数据提取 + 补充提问 Skill，自动生成 Is/IsNot 表格和根本性问题总结，作为 D2 的结构化输出。

敏捷方法

先让用户用起来，再持续迭代。Sprint 3 即交付 UI MVP，Sprint 4 放给用户试用。Skill 和知识库在每个 Sprint 末尾 Review 后迭代更新，形成使用 → 反馈 → 优化的闭环。

交付范围

D2 阶段完整闭环：产品数据提取、多轮补充提问、Is/IsNot 表格生成、根本性问题总结。知识库含产品文档与 8D 方法论资料，部署在 SharePoint / 公盘。最终输出可直接作为 D3（临时遏制措施）和 D4（根本原因分析）的输入。

核心原则

01

单产品切入

先聚焦一种产品打磨流程，验证后再扩展

02

Skill 先行

手动问答沉淀逻辑后再固化成 Skill，不急于自动化

03

早交付早反馈

Sprint 3 出 MVP，Sprint 4 让真实用户上手

04

知识库与 Skill 共进化

每次迭代同步更新知识库和 Skill 逻辑

产品架构

采用分层架构设计，各层解耦、可独立迭代。Skill 层是核心，知识库层提供数据支撑，UI 层面向用户。所有层运行在 MAICO 平台之上，利用平台提供的 LLM Gateway、Storage 和 Artifact 能力。

迭代策略

Skill 迭代循环

使用 → 用户实际运行 Skill

评估 → 检查提取精度、提问质量

优化 → 调整 Prompt、补充规则

发布 → 新版本上线

节奏：每个 Sprint 末尾 Review 后迭代

知识库迭代循环

发现缺口 → Skill 提问时发现资料缺失

补充文档 → 收集并上传到 SharePoint

更新引用 → Skill 关联新文档

验证 → 重新运行确认效果

节奏：持续发现，每两周批量更新

UI 迭代循环

用户使用 → 真实场景操作

收集反馈 → UX 问题、功能需求

优化交互 → 改进流程和视觉

发布新版本 → Artifact 更新

节奏：Sprint 4 起持续，Bug 即时修复
