01 · The brief

为什么做这个

小组要做一个 Vibe Coding + Dify 的 use case 分享。我们没有满足于一个玩具 demo——做了一个真正可以用的产品。

问题

AI 行业每天产生太多信息

26 位顶级 builders 在 X 上的推文、Latent Space 这类播客每周新一集、Anthropic 官博的新文章——想跟上这些信息，每天要花一两个小时刷各种 feed。

市面上的资讯聚合产品要么充满网红噪音，要么把所有人的内容机械地堆在一起。

愿景

让 AI 帮你做编辑

追踪一份精选过的 builders 名单，每天用 AI 把他们的内容提炼成一份有判断的中文日报，9 点准时送到收件箱。

用户填邮箱订阅后，系统自动接管所有事——抓内容、做摘要、按偏好发送、记录订阅状态。一次性、无人值守。

04 · Core features

产品做了什么

四个核心能力。每一个都不是 mock，都是真实可用的。

F.01

AI 编辑过的资讯流

不是简单聚合推文，而是用 LLM 提炼每位 builder 的核心观点，加上"今日 Insight"——把当天 builders 共同关心的话题总结成一句话。

LLM · DeepSeek V4 Pro
Style · 报刊文化版语气
Tokens · ~1500/次
F.02

订阅 → 自动入库 → 欢迎邮件

用户在订阅页填邮箱、选话题、选频率，提交后立刻收到一封欢迎邮件。订阅者数据持久化到 GitHub 仓库的 JSON 文件，所有人都能审查数据。

Webhook · Dify Trigger
Storage · GitHub Contents API
Welcome · Resend SMTP
F.03

定时自动推送

每天早上 9 点 Workflow 自动跑——抓数据、生成内容、读订阅者列表、按 daily/weekly 偏好过滤、循环发送。无需任何人工触发。

Schedule · Cron 0 9 * * *
Iteration · 循环每位订阅者
Filter · 按 frequency 分流
F.04

人文报刊风格的邮件设计

暖纸色背景、Newsreader 斜体衬线标题、墨蓝色链接。不是模板化的科技产品邮件，更像一份编辑过的副刊。

用到的技术

AI Orchestration
Dify
公司部署的 Dify 实例。两个 Workflow 共 14 个节点。所有 AI 编排、HTTP 调用、循环、判断都在这里完成。

06 · The timeline

7 天的进度

从一句想法到完整产品上线。每天都有可演示的产出。

Day 01
立项 + 设计

确定方向、做 UI 设计 spec、定 Vibe Coding prompt。完成网站静态版本，部署到 GitHub Pages。

Day 02
搭 Workflow A 主链路

在 Dify 上搭定时触发器、抓 feed、Code 数据预处理、LLM 中文摘要、HTML 邮件渲染、Resend 发邮件。第一封 AI 生成的日报到达邮箱。

Day 03
搭 Workflow B + 订阅闭环

搭订阅 Webhook、用 GitHub Contents API 持久化订阅者数据、IF/ELSE 分流、Template 节点返回错误。Workflow A 改造为循环发送给所有订阅者。

Day 04
前端对接 + 解决 CORS

前端订阅按钮真发请求，遇到 CORS 跨域问题。搭建 Cloudflare Worker 代理，10 行代码解决。整条链路打通。

Day 05
搬迁到公司 Dify

导出个人 Dify 的 DSL 文件，导入公司 Dify。重新配置凭证。邮件改用公司域名发送，解决"发到任意公司邮箱"的限制。

Day 06
打磨 · 写文档

调 Prompt 提升摘要质量。加个性化称呼。撰写产品 spec、UI spec、技术深挖文档。准备小组分享材料。

Day 07
分享 · 上线

小组内部分享。订阅者数据真实导入。第一批同事订阅后明早 9 点会真实收到日报。

07 · Lessons learned

这一周学到的事

关于 AI 编排

Dify 比想象中能干

过去以为 Dify 只能做 chatbot。这一周发现它本质是一个可视化的 backend——HTTP 调用、循环、判断、定时器、Webhook 一应俱全。

14 个节点串起一整套生产系统，没写一行后端代码。复杂度被节点的可视化吸收了。

关于 Vibe Coding

设计比代码更重要

用自然语言生成代码已经很可靠。瓶颈不在能不能让 AI 写出 React 组件，而在能不能描述清楚一个有判断力的设计。

花在 UI spec 和 prompt 上的时间，几倍地放大了 Vibe Coding 的产出质量。

关于真实工程

玩具 demo 和真实产品的差距，是细节

每个节点 demo 通过不代表整体工作。CORS、Resend 域名限制、PowerShell 的 curl 不是 curl、Iteration 的 error response method、变量绑定的嵌套层级。

这些"小问题"是产品和 demo 的真实差距。

关于可复制性

这套架构可以做很多事

  • 把 follow-builders 换成公司内部 Confluence，做内部知识周报
  • 换成竞品监控 RSS，做销售情报推送
  • 换成 SAP 系统的工单数据，做异常告警日报
  • 换成 Salesforce 的客户数据,做团队晨会简报

Workflow 是模板，内容是变量。
